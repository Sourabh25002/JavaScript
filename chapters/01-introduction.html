Chapter 01

Introduction to JavaScript

1.1 Exploring JavaScript

JavaScript is a high-level, dynamic, interpreted language that supports both object-oriented and functional styles of programming.

What these words mean

  • High-level — code reads close to human language. JavaScript takes care of memory and hardware details for you.
  • Dynamic — a variable can hold any type of value, and that can change while the program runs. The type belongs to the value, not the variable — that's why JavaScript variables are called untyped.
  • Interpreted — you run the code directly; there's no compile step for you to do. Behind the scenes, engines like V8 (Chrome, Node) still turn it into machine code while it runs to make it fast — this is called JIT (Just-In-Time) compilation.
  • Object-oriented — you can organise code around objects that hold data together with the functions that work on that data.
  • Functional — you can build programs from small functions, and pass functions around like any other value.

JavaScript vs ECMAScript

  • ECMAScript (ES) is the official rulebook (the standard). JavaScript is the language that follows it.
  • ES6 (2015) was the biggest update — it added let/const, arrow functions, classes, modules, Promises and more.
  • Since 2015, a new version comes out every year, named by year (ES2020, ES2021…).
  • Strict mode ("use strict") turns some silent mistakes into real errors — for example, using a variable you never declared. Code inside classes and modules is always strict.

Host environment

  • JavaScript on its own can't take input or show output. The host environment it runs inside provides that — along with networking, storage and graphics.
  • Web browser — the most common host. Input comes from the mouse, keyboard and network requests; output is shown on the page using HTML and CSS.
  • Node — runs JavaScript outside the browser and gives it access to the whole operating system: files, network, and running web servers.

1.2 Hello World

  • console.log() prints any value — to the terminal in Node, or to the DevTools console in a browser.
  • Run with Node: save code in a file and run node hello.js in the terminal.
  • Run in a browser: link the file from an HTML page with <script src="hello.js"></script>, open the page, and check the DevTools console.

1.3 A Tour of JavaScript

A quick preview of the whole language — each topic is covered properly in later chapters. Only these points are worth remembering now:

  • Expression vs statement — an expression produces a value (x + 1). A statement does something (let x = 5;, if, for).
  • + with strings joins them instead of adding: "3" + "2" gives "32", not 5.
  • Use ===, not == — === checks value and type, so it has no surprises. (Why == is risky comes in Chapter 3.)
  • ?. (optional chaining) — reads a nested property safely. If something in the chain is missing, you get undefined instead of an error.
