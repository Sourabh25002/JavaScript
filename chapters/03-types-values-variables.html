Chapter 03

Types, Values, and Variables

  • A value is any piece of data your program works with, like 42, "hello" or true.
  • A type is the kind of value: a number, a piece of text (a string), true/false (a boolean), and so on.
  • The type decides what you can do with a value. You do maths with numbers; you change text to uppercase or split it into words.

3.1 Overview and Definitions

Every JavaScript type belongs to one of two groups:

1. Primitive types: simple, single values

  • number: 42, 3.14
  • string: text, like "hello"
  • boolean: true or false
  • null: means "empty on purpose"
  • undefined: means "no value has been given yet"
  • symbol: a unique ID value (rarely used)
  • bigint: whole numbers too big for a normal number

2. Object types: everything else

  • Plain objects { name: "Sourabh" }, arrays [1, 2, 3], functions, dates and so on.
  • An object isn't a single value; it's a collection of values grouped together.
  • Each item inside an object is a property, which is a name + value pair. The value can be a primitive or another object. In { name: "Sourabh", age: 25 }, name and age are property names.
  • Plain object: you get values out by name (user.name), not by position.
  • Array: a special kind of object that keeps values in order, and you get them out by number (list[0], which starts counting from 0). It has its own [ ] syntax and some extra built-in behaviour.
  • Functions and classes are objects too, just special ones. (Details in Chapters 8 and 9.)

The big practical difference between the two groups: primitives can't be changed, objects can. They also behave differently when you compare or copy them. All of that is in 3.8.

Interview: "How many primitive types does JavaScript have?" Seven: number, string, boolean, null, undefined, symbol and bigint. Anything else is an object.

Garbage collection: memory is cleaned up for you

  • Every value your program creates takes up some memory.
  • Garbage collection means JavaScript frees that memory automatically once a value can't be reached anymore, meaning no variable or object points to it.
  • So you never free memory yourself, unlike in languages such as C.

Methods work on every value except null and undefined

  • A method is a function that belongs to a value. You call it with a dot: value.method().
  • Strictly speaking, only objects have methods. But strings, numbers and booleans act as if they have methods too.
  • How? JavaScript quietly wraps the primitive in a temporary object (a String, Number or Boolean), runs the method on that object, then throws the wrapper away. This is called autoboxing.
"hello".toUpperCase()   // "HELLO"   (string)
(3.14159).toFixed(2)    // "3.14"    (number)
true.toString()         // "true"    (boolean)
[1, 2, 3].join("-")     // "1-2-3"   (array, already an object)
  • null and undefined are the only values with no wrapper and no methods. They mean "no value", so there's nothing to call a method on.
  • Putting a dot after them crashes with a TypeError. This is one of the most common errors in real code:
let user;               // undefined: no value given yet
user.name;
TypeError: Cannot read properties of undefined (reading 'name')

It usually means a variable you expected to hold an object is still empty. The safe way is optional chaining, user?.name, which gives undefined instead of crashing (more in Chapter 4).

Interview: "If strings are primitives, how does "abc".toUpperCase() work?" Autoboxing: JavaScript wraps the string in a temporary String object just for that call.

3.2 Numbers

  • JavaScript has only one number type for both whole numbers and decimals. There's no separate "int" and "float" like in Java or C.
  • Whole numbers are exact only up to 253 − 1 (about 9 quadrillion), saved as Number.MAX_SAFE_INTEGER. Past that, the last digits can come out wrong: 2 ** 53 + 1 === 2 ** 53 is true. For bigger numbers, use BigInt (below).
  • You can write 1_000_000 instead of 1000000. The underscores are only there to make it easier to read.
  • Useful Math functions: round, floor (rounds down), ceil (rounds up), trunc (just cuts off the decimals), max, min, abs and random (a number from 0 up to, but not including, 1).
  • floor and trunc only differ for negative numbers: Math.floor(-3.5) is -4, but Math.trunc(-3.5) is -3.

Maths never throws an error: Infinity and NaN

  • Dividing by zero is not an error. 1/0 gives Infinity and -1/0 gives -Infinity.
  • Maths that makes no sense gives NaN ("Not a Number"). For example: 0/0, "abc" * 2 or Math.sqrt(-1).
  • Trap: typeof NaN is "number". NaN is a special value of the number type.
  • NaN is not equal to anything, not even itself. So x === NaN is always false. Use Number.isNaN(x) to check.
NaN === NaN            // false
Number.isNaN(NaN)      // true
isNaN("abc")           // true:  the old global isNaN turns "abc" into a number first (NaN)
Number.isNaN("abc")    // false: "abc" is a string, not NaN

Interview: "What is typeof NaN?" "number". "How do you check for NaN?" Number.isNaN(x). x === NaN never works, because NaN never equals itself.

0.1 + 0.2 is not 0.3

  • Numbers are stored in binary (base 2). Fractions like 1/2 or 1/4 fit exactly, but 0.1 can't be stored exactly, just like 1/3 can't be written exactly in decimal (0.333…). So a tiny error creeps in.
0.1 + 0.2            // 0.30000000000000004
0.1 + 0.2 === 0.3    // false
  • This is not a JavaScript bug. Python, Java, C and most other languages store decimals the same way.
  • Fixes:
    • For money, work in whole numbers (paise, not rupees).
    • To compare, check that the numbers are close enough: Math.abs(a - b) < Number.EPSILON.
    • For display, round with (0.1 + 0.2).toFixed(2), which gives "0.30".

Interview: "Why is 0.1 + 0.2 !== 0.3?" 0.1 and 0.2 can't be stored exactly in binary, so the sum is off by a tiny amount. It happens in most languages, not just JavaScript.

BigInt: whole numbers of any size

  • A separate primitive type for whole numbers bigger than the safe limit. Write it with an n at the end (123n) or use BigInt("123").
  • You can't mix BigInt and normal numbers in maths. 1n + 1 throws a TypeError. Convert one side first: 1n + BigInt(1).
  • Division drops the decimals: 7n / 2n is 3n.
  • Comparing across the two types works: 1 < 2n is true. 0 == 0n is also true, but 0 === 0n is false, because === also checks that the types match.

Dates

  • Covered in Chapter 11. For now, just know that Date.now() gives the current time as a timestamp: the number of milliseconds since 1 January 1970.

3.3 Text

  • A string is a piece of text. It's immutable (see 3.8) and counted from 0: s[0] is the first character, and s.length is the length.
  • There's no separate "character" type. A single character is just a string of length 1.
  • You can use 'single', "double" or `backtick` quotes. Only backticks allow a string to span several lines and to contain ${…} (see below).
  • Useful escape codes: \n for a new line, \' for a quote inside a quoted string, and \\ for a backslash.

Common string methods

let s = "Hello, world";

s.slice(0, 5)          // "Hello"  (the end position isn't included)
s.slice(-5)            // "world"  (negative counts from the end)
s.split(", ")          // ["Hello", "world"]
s.indexOf("o")         // 4  (-1 if not found)
s.includes("world")    // true
s.startsWith("Hell")   // true
s.replace("l", "L")    // "HeLlo, world": only the FIRST match
s.toUpperCase()        // "HELLO, WORLD"
"  hi  ".trim()        // "hi"
"5".padStart(3, "0")   // "005"
"ab".repeat(3)         // "ababab"
  • None of these change s. They all return a new string, because strings are immutable.
  • replace only changes the first match. Use replaceAll to change every match.
  • substring works like slice, but treats negative numbers as 0. Stick with slice.
  • Comparing strings with < or > goes character by character using character codes, and all capital letters come before all small letters. So "Zebra" < "apple" is true.

Template literals (backtick strings)

let name = "Sourabh";
`Hi ${name}, 2 + 3 = ${2 + 3}`
"Hi Sourabh, 2 + 3 = 5"
  • Any expression can go inside ${ }. Its result is turned into a string and dropped in. This is cleaner than joining strings with +.
  • They can span several lines without needing \n.
  • Tagged templates: if you put a function name right before the backtick (fn`text`), that function gets the text pieces and the values and builds the result. Libraries use this, e.g. for safely building HTML or SQL. Details in Chapter 14.

Trap: length doesn't always count characters

  • JavaScript stores text in UTF-16, a format that keeps text in 16-bit pieces. Most characters take one piece, but emoji and some rare characters take two.
  • length counts the pieces, not the characters you see.
"😀".length          // 2
[..."😀"].length     // 1: spreading (...) splits by real characters
for (let ch of "hi😀") console.log(ch);   // h, i, 😀 (for...of also goes by real characters)

Pattern matching (regular expressions, /pattern/) is skipped here. It's covered properly in Chapter 11.

Interview: "Why is "😀".length 2?" Strings are stored as 16-bit pieces, and an emoji needs two. Use [...str].length to count real characters. "What's the difference between slice and substring?" Only slice accepts negative numbers.

3.4 Boolean Values

  • A boolean is either true or false. You usually get one from a comparison like a === 4.

Truthy and falsy

  • When JavaScript needs a true/false answer (in if, while, &&, || or !), it converts any value into a boolean.
  • These 8 values are falsy, meaning they act like false: false, 0, -0, 0n, NaN, "" (empty string), null and undefined.
  • Everything else is truthy, meaning it acts like true. That includes some values that look "empty" or "false":
if ([])      // runs: an empty array is truthy
if ({})      // runs: an empty object is truthy
if ("0")     // runs: a non-empty string
if ("false") // runs: a non-empty string
if (" ")     // runs: a space is still a character

Trap: if (x) also skips 0 and ""

A shortcut like if (x) skips every falsy value, not just null and undefined. That's a bug when 0 or "" is a real value in your program:

let count = 0;
if (count) { … }               // doesn't run, even though 0 is a real count
if (count !== undefined) { … } // runs: checks only what you meant
  • && (AND), || (OR) and ! (NOT) work with any values, not just booleans. !!x is a quick way to turn any value into true or false. Full details in Chapter 4.

Interview: "What are the falsy values?" false, 0, -0, 0n, NaN, "", null and undefined. "Is [] truthy?" Yes. Every object is truthy, even an empty one.

3.5 null and undefined

  • Both mean "no value", but they're used differently:
    • null means "empty on purpose". You set it, to say "there's nothing here".
    • undefined means "nothing has been set yet". JavaScript gives it to you automatically.
  • You get undefined when:
    • a variable was declared without a value: let x;
    • you read an object property that doesn't exist: user.phone
    • a function doesn't return anything
    • you call a function without passing one of its parameters
  • typeof null is "object". This is a bug from the very first version of JavaScript. It was never fixed because fixing it would break old websites. typeof undefined is "undefined".
  • null == undefined is true, but null === undefined is false.
  • Both are falsy, and both throw a TypeError if you use a dot on them (see 3.1).
  • When you want to say "no value" yourself, use null. Leave undefined for JavaScript.

Interview: "What's the difference between null and undefined?" undefined means a value was never set, and JavaScript gives it automatically. null is set by you, on purpose, to mean "empty". Expect the follow-up "what is typeof null?" It's "object", an old bug.

3.6 Symbols

  • A Symbol is a primitive used as a property name that can never clash with any other property name.
  • Every call to Symbol() gives a brand-new, unique value, even with the same description:
let id = Symbol("id");
Symbol("id") === Symbol("id")   // false: every symbol is unique

let user = { name: "Sourabh" };
user[id] = 101;                  // a property no other code can overwrite by accident
  • Why they exist: JavaScript uses built-in symbols like Symbol.iterator to add new features to objects without breaking old code that might already use a normal property name like "iterator" (Chapter 12).
  • Symbol.for("key") is the exception. It returns the same symbol every time for the same key, so different parts of a program can share one symbol.
  • Symbols are rare in everyday code. Just know what they are and why they exist.

3.7 The Global Object

  • The global object is a built-in object whose properties are all the things you can use anywhere without importing them: undefined, NaN, Infinity, parseInt(), Math, JSON, Date and so on.
  • Its name depends on where your code runs: window in browsers and global in Node. globalThis works everywhere, so prefer it.
  • A top-level var becomes a property of this object, but let and const don't (see 3.10).

3.8 Immutable Primitive Values and Mutable Object References

This section is about how primitives and objects behave differently. There are three differences:

  • Primitives can't be changed, are compared by value, and get copied when you assign them.
  • Objects can be changed, are compared by reference, and get shared (not copied) when you assign them.

The key idea behind all three: an object variable doesn't hold the object itself. It holds a reference, which is like an address pointing to where the object lives in memory.

1. Changing: objects are mutable, primitives are immutable

  • Mutable means a value can be changed after it's created. Immutable means it can't.
  • Objects can be changed in place. You can edit, add or remove what's inside, and it's still the same object.
  • Primitives can never be changed. Anything that looks like a change actually creates a new value. String methods never touch the original string; they return a new one, which you must store if you want to keep it.
let user = { name: "Sourabh" };
user.name = "Rahul";    // same object, new contents

let s = "hello";
s[0] = "H";             // silently does nothing
s.toUpperCase();        // returns "HELLO", but s is unchanged
s = s.toUpperCase();    // store the result: s now points to "HELLO"
  • Reassigning is not mutating. Reassigning means pointing a variable at a different value (x = 10), and any let variable can do it. Mutating means changing the inside of a value, which only objects allow.
  • So const doesn't freeze an object. It only stops reassignment. The contents can still change:
const user = { name: "Sourabh" };
user.name = "Rahul";    // ✅ allowed: changes the object
user = {};              // ❌ TypeError: can't reassign a const

2. Comparing: by value vs. by reference

  • Primitives are equal if their values are the same: "abc" === "abc" is true.
  • Objects: === checks whether both point to the same object, not whether the contents match.
{ x: 1 } === { x: 1 }   // false: two different objects that just look the same
[] === []               // false: two different arrays

let a = [1, 2];
let b = a;
a === b                 // true: both point to the same array
  • To check whether two objects or arrays have the same contents, you have to compare them item by item yourself, e.g. with a loop.

3. Copying: objects are shared, not copied

let b = a copies the reference, so both names point to the same object. A change through one shows up in the other:

let a = { n: 1 };
let b = a;              // b points to the SAME object, not a copy
b.n = 2;
console.log(a.n);
2

With primitives this can't happen. let b = a gives b its own value, so changing b never affects a.

  • To make a real copy, use [...arr] or Array.from(arr) for arrays, and { ...obj } for objects.
  • These are shallow copies: only the top level is copied, and objects nested inside are still shared. For a full deep copy, use structuredClone(obj).
let user = { name: "Sourabh", address: { city: "Delhi" } };
let copy = { ...user };
copy.name = "Rahul";            // doesn't affect user
copy.address.city = "Mumbai";   // DOES affect user: address is still shared

Interview: "Can you change a const object?" Yes, its properties can change. const only stops reassignment. Use Object.freeze(obj) to make it read-only.

"Are strings mutable?" No. Every string method returns a new string.

"Why is [] === [] false?" Objects are compared by reference, and these are two separate arrays.

"Shallow vs. deep copy?" A shallow copy ({...obj}) copies only the top level. A deep copy (structuredClone) copies nested objects too.

3.9 Type Conversions

  • When an operation needs a different type, JavaScript converts the value automatically. This is called type coercion.
  • The rule for +: if either side is a string, + joins them as text. All the other maths operators (-, *, /, %) always convert to numbers.
"5" + 1          // "51": + with a string joins text
"5" - 1          // 4:    - always does maths
"7" * "4"        // 28
1 - "x"          // NaN:  "x" can't become a number
10 + " apples"   // "10 apples"

Surprising conversions to a number

Number("")          // 0
Number("  12  ")    // 12:  spaces at the ends are ignored
Number("12px")      // NaN: anything extra makes it NaN
Number(true)        // 1    (false → 0)
Number(null)        // 0
Number(undefined)   // NaN

== vs ===

  • === (strict equality) never converts. If the types are different, the answer is false. Use this almost always.
  • == (loose equality) converts the values first, then compares. That gives confusing results:
null == undefined   // true
"0" == 0            // true:  "0" becomes 0
0 == false          // true:  false becomes 0
"0" == false        // true:  both become 0
"" == 0             // true

undefined == false  // false! being falsy doesn't mean == false
null == 0           // false
  • Being falsy and being == false are different things. if turns a value into a boolean, but == never does. That's why undefined is falsy, yet undefined == false is false.
  • The one common use of ==: x == null is true for both null and undefined, so it checks both in one go.

Interview: "== vs ===?" === checks value and type with no conversion. == converts the types first, so "0" == 0 is true. "What are "5" + 1 and "5" - 1?" "51" and 4.

Converting on purpose

  • Use Number(x), String(x) and Boolean(x). Short forms you'll see in code: +x (to number), x + "" (to string) and !!x (to boolean).
  • Never use new Number(), new String() or new Boolean(). They create wrapper objects, not primitives: typeof new Number(5) is "object", and new Boolean(false) is truthy because it's an object.
  • Number() vs parseInt()/parseFloat(): Number() needs the whole string to be a number. parseInt and parseFloat read digits from the start and stop at the first character that doesn't fit.
Number("42px")          // NaN
parseInt("42px")        // 42
parseFloat("3.14 kg")   // 3.14
parseInt("3.99")        // 3:   whole numbers only, it just cuts the rest
parseInt("px42")        // NaN: it has to start with a number
parseInt("ff", 16)      // 255: the second argument is the base
  • n.toFixed(2) rounds to 2 decimal places, but returns a string, not a number: (3.456).toFixed(2) is "3.46".

Objects to primitives (simplified)

  • Every object is truthy. No conversion is needed for that.
  • To turn an object into a string or number, JavaScript calls the object's own valueOf() or toString() method. For plain objects and arrays, it ends up using toString():
    • A plain object becomes "[object Object]".
    • An array becomes its items joined by commas: [1, 2] becomes "1,2", and [] becomes "".
  • That explains the weird puzzles:
[] + []          // "":  both become "" and get joined
[] + {}          // "[object Object]"
Number([])       // 0:   [] → "" → 0
`${{ a: 1 }}`    // "[object Object]": why printing an object in a string looks useless
  • Dates are the exception: date1 < date2 works, because dates turn into their timestamp numbers for comparisons.

3.10 Variable Declaration and Assignment

let and const

  • let creates a variable you can reassign later. If you don't give it a value, it starts as undefined.
  • const creates a constant. You must give it a value straight away, and reassigning it throws a TypeError. (A const object's contents can still change; see 3.8.)
  • A common habit: use const by default, and switch to let only when the value really needs to change.
  • const works in for...of loops, e.g. for (const item of list), because each loop round gets a fresh constant. It doesn't work in a normal for (let i = 0; …; i++) loop, because i++ reassigns.
  • Variables have no fixed type. let x = 10; x = "ten"; is allowed. (TypeScript adds types on top of JavaScript.)

Block scope

  • Scope is the part of the code where a variable exists.
  • let and const are block scoped. They exist only inside the { } they were declared in: an if, a loop, a function and so on.
if (true) {
  let msg = "hi";
}
console.log(msg);
ReferenceError: msg is not defined
  • Declaring the same name twice with let or const in the same scope is a SyntaxError. An inner block can declare a variable with the same name as an outer one. This is called shadowing. It's allowed, but confusing.
  • A variable declared outside every block is global and can be used everywhere.

var: the old way, and why let replaced it

Before ES6 (2015), var was the only way to declare a variable. You'll still see it in old code, and interviewers love asking how it differs from let:

  1. Function scope, not block scope. A var inside an if or a loop leaks out of that block. It's only contained by a function.
  2. Hoisting. JavaScript quietly moves the var declaration to the top of the function. So you can use the variable before its line and get undefined instead of an error, which hides bugs.
  3. Can be declared again. var x = 1; var x = 2; is allowed.
  4. A top-level var becomes a property of the global object (window.x). This doesn't happen with let and const.
console.log(a);   // undefined: var is hoisted, no error
var a = 5;

console.log(b);   // ReferenceError: can't use it before this line
let b = 5;
  • let and const are technically hoisted too, but you can't touch them until their line runs. The stretch of code before that line is called the Temporal Dead Zone (TDZ). Using the variable there throws a ReferenceError.
  • If you assign to a name you never declared (x = 5 without let), JavaScript quietly creates a global variable. In strict mode ("use strict", a safer mode of JavaScript), it throws an error instead.

Classic trap: var in a loop

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));   // runs later, after the loop ends
}
3 3 3

With var, there's one shared i for the whole loop. By the time the functions run, it's already 3. Change it to let i and each loop round gets its own i, so it prints 0 1 2.

Interview: "var vs let vs const?" var is function scoped, can be redeclared, and is hoisted as undefined. let and const are block scoped and can't be used before their line (the TDZ). const also can't be reassigned. "Are let and const hoisted?" Yes, but the TDZ stops you from using them early.

Destructuring

Destructuring is a short way to unpack values from an array or object into separate variables.

// Arrays: by position
let [a, b] = [1, 2];              // a = 1, b = 2
[a, b] = [b, a];                  // swap: a = 2, b = 1
let [x, , z] = [1, 2, 3];         // an empty comma skips: x = 1, z = 3
let [first, ...rest] = [1, 2, 3]; // first = 1, rest = [2, 3]

// Objects: by property name (order doesn't matter)
let user = { name: "Sourabh", age: 25 };
let { name, age } = user;         // name = "Sourabh", age = 25
let { name: userName } = user;    // rename: userName = "Sourabh"
let { city = "Delhi" } = user;    // default value if the property is missing
  • Array destructuring goes by position. Object destructuring goes by property name.
  • If a value is missing, the variable gets undefined, or the default if you gave one.
  • It's handy in loops: for (const [key, value] of Object.entries(user)) gives each property's name and value.
  • Nested destructuring is possible, but quickly gets hard to read. Keep it simple.

Interview: "How do you swap two variables without a temporary variable?" [a, b] = [b, a];

3.11 Summary

The book's summary is just a recap. Here's a quick revision list of what to remember for interviews instead:

  • 7 primitives: number, string, boolean, null, undefined, symbol, bigint. Everything else is an object.
  • Primitives get methods through autoboxing. A dot on null or undefined throws a TypeError.
  • typeof NaN is "number". NaN !== NaN, so check with Number.isNaN.
  • 0.1 + 0.2 !== 0.3, because of how binary stores decimals.
  • Safe whole numbers stop at 253 − 1. Use BigInt beyond that, and don't mix BigInt with normal numbers.
  • "😀".length is 2. String methods return new strings.
  • The 8 falsy values: false, 0, -0, 0n, NaN, "", null, undefined. [] and {} are truthy.
  • undefined means never set; null means empty on purpose. typeof null is "object".
  • Objects are mutable, compared by reference and shared on assignment. [] === [] is false. const objects can still change.
  • Shallow copy: {...obj}. Deep copy: structuredClone(obj).
  • "5" + 1 is "51" and "5" - 1 is 4. Use ===, not ==.
  • var is function scoped and hoisted as undefined. let/const are block scoped and have a TDZ.
  • The var loop trap prints 3 3 3; with let it prints 0 1 2.
