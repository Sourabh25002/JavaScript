Chapter 02

Lexical Structure

Lexical structure = the basic writing rules of a language: how names are written, how comments work, and how one statement ends and the next begins.

2.1 The Text of a JavaScript Program

  • Case-sensitive — name, Name and NAME are three different variables. Keywords must be lowercase (while, not While).
  • Spaces and line breaks between pieces of code are ignored, so you can format code however you like. (One exception — see 2.6.)

2.2 Comments

  • // — comments out the rest of the line.
  • /* ... */ — can cover many lines, but can't be placed inside another /* */.

2.3 Literals

  • A literal is a value written directly in the code — 12, 1.2, "hello", true, null.

2.4 Identifiers and Reserved Words

  • An identifier is just a name — for a variable, function, class, etc.
  • It must start with a letter, _ or $. Digits are allowed after the first character, but never first — that's how JavaScript tells names apart from numbers.
  • Reserved words (if, for, class, let, return…) can't be used as variable or function names. They're fine as object property names.
  • Also avoid naming things arguments or eval.

2.5 Unicode

  • JavaScript code is written in Unicode, so strings and comments can contain any language or emoji.
  • Names can use non-English letters too (but not emoji) — in practice, stick to English letters.

2.6 Optional Semicolons

JavaScript can add missing semicolons for you — this is called ASI (Automatic Semicolon Insertion). But it only adds one at a line break when the next line can't continue the current statement. So sometimes it joins lines you meant to keep separate, or splits lines you meant to keep together.

Trap 1: line break after return

JavaScript always ends the statement right after return if a line break follows — so the function returns undefined.

function getUser() {
  return
  { name: "Sourabh" };
}
getUser();
undefined

Fix: keep the value on the same line as return. Same rule for break, continue and throw.

Trap 2: line starting with ( or [

JavaScript treats it as a continuation of the previous line, so two lines become one statement. Fix: end the previous line with a semicolon.

Other rules

  • ++ and -- must be on the same line as the variable they apply to.
  • In arrow functions, => must be on the same line as the parameters.

Simplest habit: always write semicolons (or let a formatter like Prettier add them).
